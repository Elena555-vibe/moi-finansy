# Спецификация MVP: личные финансы

**Версия:** 1.0  
**Статус:** готово к передаче агенту-разработчику  
**Язык интерфейса:** русский  
**Целевая среда:** iPhone / Safari, вертикальная ориентация, устанавливаемое PWA

## 1. Назначение продукта

Личное мобильное веб-приложение для одного пользователя, которое помогает ежедневно фиксировать доходы и расходы, соблюдать месячный лимит и откладывать деньги на обязательную выплату долга.

Продукт не является универсальной домашней бухгалтерией. Его ключевой вопрос: **«Сколько я ещё могу безопасно потратить в этом месяце?»**

### Цели MVP

- Быстро и вручную фиксировать фактические доходы и расходы.
- Показывать доступный остаток и остаток лимита на текущий месяц.
- Планировать резерв на выплату долга и отслеживать фактически отложенную сумму.
- Учитывать будущие платежи как напоминания.
- Показывать структуру расходов по категориям.
- Работать локально и без подключения к интернету.

### Критерий успеха продукта

После месяца использования пользователь понимает фактическое распределение трат, укладывается в установленный лимит и способен накопить необходимую сумму для обязательного платежа по долгу.

## 2. Продуктовые принципы

1. **Минимум полей.** Для обычной операции нужны только сумма, дата и категория/источник.
2. **Финансовый план важнее отчётности.** Главный экран прежде всего показывает остаток лимита.
3. **Фактические и плановые деньги разделены.** Плановый доход не изменяет реальный баланс; резерв, который уже фактически отложен, уменьшает свободные деньги.
4. **Все действия обратимы.** Операции можно редактировать и удалять; показатели пересчитываются сразу.
5. **Мобильный приоритет.** Интерфейс должен быть понятен и удобен на iPhone одной рукой.

## 3. Объём MVP

### Входит в MVP

- Первоначальная настройка: начальный остаток, долг, категории, план текущего месяца.
- План месяца: планируемый доход, плановый резерв на долг, автоматически вычисляемый месячный лимит.
- Операции: расход, доход, резерв, будущий платёж (напоминание), платёж по долгу.
- Редактирование и удаление операций.
- Главный экран с ключевыми показателями и диаграммой расходов.
- Список операций, сгруппированный по датам.
- Управление категориями, источниками дохода и данными долга.
- Локальное офлайн-хранение, PWA и работа без сети.

### Не входит в MVP

- Интеграции с банками, импорт выписок, распознавание чеков.
- Авторизация, облачная синхронизация, резервное копирование и экспорт.
- Несколько пользователей, семейный бюджет, несколько счетов и валют.
- Копейки, подкатегории, комментарии, названия операций, файлы и чеки.
- Автоматический расчёт процентов, график погашения долга, несколько накопительных целей.
- Лимиты по категориям, сравнение месяцев, расширенная аналитика.
- Push-уведомления, PIN-код, биометрия, автоматическая блокировка.
- Полноценная десктопная версия и переключатель светлой/тёмной темы.

## 4. Роли и хранение данных

| Параметр | Решение |
|---|---|
| Пользователь | Один локальный пользователь |
| Авторизация | Отсутствует |
| Хранилище | Только на устройстве в браузере |
| Рекомендуемая реализация | IndexedDB для предметных данных; localStorage допустим только для простых настроек |
| Синхронизация | Отсутствует |
| Офлайн-режим | Обязателен |

> Важно: при очистке данных Safari, удалении PWA или потере телефона история может быть утрачена. Это принятое ограничение MVP.

## 5. Информационная архитектура и навигация

Нижняя навигация состоит ровно из четырёх разделов:

| Раздел | Назначение |
|---|---|
| Главная | Текущее финансовое состояние и распределение расходов |
| Операции | История доходов, расходов, резервов, платежей и напоминаний |
| План | План текущего календарного месяца и прогресс резерва |
| Настройки | Начальный остаток, категории, источники дохода, долг |

На всех основных экранах доступна плавающая кнопка **«+»**. Она открывает меню выбора: **Расход**, **Доход**, **Резерв**, **Будущий платёж**.

```text
Главная → «+» → тип операции → полноэкранная форма → «Сохранить» → Главная
```

## 6. Финансовая модель и расчёты

### 6.1 Термины

| Термин | Определение |
|---|---|
| Начальный остаток | Сумма денег на дату начала учёта, введённая при первом запуске |
| Планируемый доход | Ожидаемая общая сумма доходов месяца; не является фактическим поступлением |
| Плановый резерв | Сумма, которую нужно накопить на долг в текущем месяце |
| Фактический резерв | Сумма операций «Резерв» за вычетом использованного для платежей по долгу резерва |
| Обычный расход | Расход, уменьшающий повседневный месячный лимит |
| Платёж по долгу | Фактический расход для погашения долга, не уменьшающий повседневный лимит |
| Будущий платёж | Напоминание о предполагаемом расходе; до оплаты не влияет на расчёты |

### 6.2 Базовые формулы

Все суммы хранятся и рассчитываются в целых рублях.

| Показатель | Формула |
|---|---|
| Месячный лимит | `планируемый доход − плановый резерв на долг` |
| Осталось потратить | `месячный лимит − сумма обычных расходов периода` |
| Общий остаток | `начальный остаток + все фактические доходы − все фактические расходы − все платежи по долгу` |
| Свободные деньги | `общий остаток − фактически отложено в резерв` |
| Осталось отложить | `плановый резерв − фактически отложено в резерв` |
| Текущий остаток долга | `первоначальная сумма долга − сумма платежей по долгу` либо вручную заданный актуальный остаток после редактирования |

**Фактический резерв** рассчитывается как:

`сумма операций «Резерв» − сумма операций «Платёж по долгу»`.

Планируемый доход и плановый резерв не меняют общий остаток: они используются для планирования лимита. Обычные расходы включают, в частности, продукты, транспорт, коммунальные платежи, подписки и связь.

### 6.3 Допустимые отрицательные значения

Сохранение не блокируется, если отрицательными становятся общий остаток, свободные деньги, остаток лимита или фактический резерв. Приложение отражает реальное состояние. При отрицательных итогах на конец месяца отображается внутреннее предупреждение.

### 6.4 Периоды

- Финансовый месяц совпадает с календарным: с 1-го по последний день месяца.
- Месяц закрывается автоматически по календарю; отдельная кнопка закрытия не нужна.
- Операции прошлых месяцев доступны для свободного редактирования и удаления.
- Любое изменение пересчитывает все зависимые показатели соответствующего и текущего периодов.
- Неиспользованный лимит не переносится отдельной механикой на следующий месяц. Следующий лимит всегда вычисляется из нового плана месяца.

## 7. Операции и правила CRUD

### 7.1 Типы операций

| Тип | Поля создания | Влияние на общий остаток | Влияние на лимит |
|---|---|---:|---:|
| Расход | сумма, категория, дата | уменьшает | уменьшает |
| Доход | сумма, источник, дата | увеличивает | не влияет |
| Резерв | сумма, дата | не влияет | не влияет |
| Будущий платёж | сумма, категория, дата | не влияет | не влияет |
| Платёж по долгу | сумма, дата, долг | уменьшает | не влияет |

### 7.2 Расход

- Поля в форме: **сумма → категория → дата → Сохранить**.
- Сегодняшняя дата подставляется по умолчанию, но её можно изменить календарём на прошлую или текущую дату.
- Если пользователь намерен указать будущую дату, он создаёт тип «Будущий платёж», а не фактический расход.
- После сохранения осуществляется переход на Главную.
- Расход можно изменить (сумма, категория, дата) и удалить через меню «⋯».
- Перед удалением обязательно показывать подтверждение, например: «Удалить операцию на 2 500 ₽?».

### 7.3 Доход

- Поля: сумма, источник дохода, дата.
- Учитываются только фактически поступившие доходы; будущие ожидаемые доходы отдельными операциями не создаются.
- Доход можно изменить и удалить; расчёты обновляются немедленно.

### 7.4 Резерв

- Поля: сумма и дата.
- Добавление резерва увеличивает фактически отложенную сумму, но не уменьшает общий остаток.
- Резерв можно изменить и удалить так же, как доход и расход.
- Разрешено добавить резерв больше текущего общего остатка; свободные деньги могут стать отрицательными.

### 7.5 Будущий платёж

- Поля: сумма, категория, дата.
- Это напоминание, а не расход: до подтверждения не меняет баланс, свободные деньги и лимит.
- За один календарный день до даты платежа на Главной и/или в Операциях показывается внутреннее предупреждение.
- По действию **«Оплачено»** открывается форма расхода с предзаполненными суммой, категорией и датой. Сумму и дату можно поправить.
- После сохранения создаётся фактический расход, а напоминание остаётся в истории со статусом **«Оплачено»**.

### 7.6 Платёж по долгу

На экране долга действие **«Зафиксировать платёж»** открывает ввод фактической суммы. После подтверждения:

1. создаётся операция «Платёж по долгу»;
2. общий остаток уменьшается на сумму платежа;
3. текущий остаток долга уменьшается на сумму платежа;
4. фактический резерв уменьшается на сумму платежа;
5. повседневный месячный лимит не изменяется.

Платёж разрешён и при недостаточном резерве. Значение фактического резерва в этом случае может стать отрицательным.

### 7.7 Минимальная техническая валидация

Не вводить сложных финансовых запретов. Однако форма не должна сохранять технически неполную запись: сумма должна быть числом больше нуля, а обязательные поля (дата и категория/источник, где применимо) должны быть заполнены. Пользователь исправляет остальные ошибки через редактирование или удаление.

## 8. Модель данных

Идентификаторы — UUID. Временные метки создания и изменения хранятся отдельно от пользовательской даты операции.

### 8.1 Сущности

| Сущность | Ключевые поля |
|---|---|
| `AppSettings` | `initialBalance`, `initialBalanceDate`, `locale`, `currency`, `onboardingCompleted` |
| `MonthlyPlan` | `id`, `yearMonth`, `plannedIncome`, `plannedDebtReserve`, `monthlyLimit` (вычисляемый или кэшированный), `createdAt`, `updatedAt` |
| `Debt` | `id`, `initialAmount`, `currentAmount`, `nextPaymentDate`, `nextPaymentAmount`, `isActive` |
| `Category` | `id`, `name`, `icon`, `sortOrder`, `isArchived` |
| `IncomeSource` | `id`, `name`, `sortOrder`, `isArchived` |
| `Transaction` | `id`, `type`, `amount`, `date`, `categoryId?`, `incomeSourceId?`, `debtId?`, `createdAt`, `updatedAt` |
| `FuturePayment` | `id`, `amount`, `date`, `categoryId`, `status` (`planned` / `paid`), `createdAt`, `updatedAt` |

### 8.2 Типы `Transaction.type`

`expense` | `income` | `reserve` | `debt_payment`

### 8.3 Требования к целостности данных

- Архивированная категория или источник не доступны при создании новых операций, но сохраняются у исторических записей.
- При удалении категории с историей она **архивируется**, а не удаляется физически.
- При редактировании или удалении платежа по долгу пересчитываются `Debt.currentAmount` и фактический резерв. Предпочтительно вычислять агрегаты из операций, чтобы не допускать рассинхронизации.
- Дата хранится как локальная календарная дата (`YYYY-MM-DD`), без смещения UTC. Отображение: `ДД.ММ.ГГГГ`.

## 9. Экраны

### 9.1 Онбординг / первоначальная настройка

Последовательность:

1. Ввести начальный остаток и дату начала учёта.
2. Добавить данные долга: первоначальная и текущая суммы, дата и сумма ближайшего платежа.
3. Проверить или настроить категории.
4. Создать план текущего месяца: планируемый доход и плановый резерв.
5. Перейти на Главную.

### 9.2 Главная

Экран показывается **без прокрутки** на целевых экранах iPhone. Главный и самый крупный элемент:

> **Осталось потратить: N ₽**

Также отображаются:

- общий остаток;
- свободные деньги;
- кольцевая диаграмма расходов текущего месяца;
- список категорий под диаграммой с суммой по каждой категории, без процентов.

Не показывать на Главной последние операции, расширенную аналитику, календарь, сравнение периодов или дополнительные информационные блоки.

### 9.3 Операции

- История группируется по датам.
- Доходы отмечены знаком `+`, расходы — знаком `−`.
- Резервы, платежи по долгу и будущие платежи имеют различимые подписи/иконки и статусы.
- Детальные фильтры и поиск не входят в MVP.
- Меню `⋯` у операции открывает доступные действия редактирования и удаления.

### 9.4 План

Минимальный экран текущего месяца:

| Поле/показатель | Поведение |
|---|---|
| Планируемый доход | Редактируется вручную |
| Плановый резерв на долг | Редактируется вручную |
| Рекомендуемый месячный лимит | Вычисляется автоматически |
| Фактически отложено | Вычисляется из операций резервов и платежей |
| Осталось отложить | `плановый резерв − фактически отложено` |
| Остаток лимита | `месячный лимит − обычные расходы` |

План допускается изменять в течение месяца; вычисления должны обновляться сразу.

### 9.5 Долг

Отображает:

- первоначальную сумму;
- текущий остаток;
- дату и сумму ближайшего платежа;
- плановый резерв текущего месяца;
- фактически отложено;
- остаток до целевого резерва;
- действия «Добавить в резерв» и «Зафиксировать платёж».

Процентная ставка и расчёт процентов отсутствуют.

### 9.6 Настройки

Доступно изменить:

- начальный остаток;
- категории: создать, переименовать, изменить иконку, порядок, архивировать;
- источники доходов: создать, переименовать, изменить порядок, архивировать;
- данные долга;
- данные первоначальной настройки при необходимости.

Кнопки «Удалить все данные», экспорта и выбора темы нет.

## 10. Справочники

### Стартовые категории расходов

- Продукты
- Транспорт
- Коммунальные платежи
- Подписки
- Связь
- Долги
- Непредвиденные расходы
- Прочее

Выбор категории в форме — вертикальный список с иконкой и названием. Последняя выбранная категория не запоминается.

### Стартовые источники доходов

- Зарплата
- Самозанятость
- Проценты по вкладу
- Прочее

Источник «Возврат» в MVP отсутствует.

## 11. PWA и офлайн

- Приложение должно быть устанавливаемым PWA с иконкой и manifest.
- После первой успешной загрузки основные ресурсы приложения должны быть доступны без сети через service worker.
- Все операции должны создаваться, редактироваться и отображаться офлайн.
- Внешний сервер и синхронизация не используются.
- Приложение должно корректно открываться из иконки на домашнем экране iPhone без необходимости пользоваться адресной строкой Safari.

## 12. Мобильные UX- и доступностные требования

- Целевая ориентация — вертикальная.
- Приоритетная ширина — типичные iPhone; минимально поддерживаемая CSS-ширина — 320 px.
- Интерфейс не должен иметь горизонтальную прокрутку.
- Формы добавления и редактирования открываются полноэкранно и корректно учитывают safe area iPhone.
- Экранная клавиатура не должна закрывать активное поле или кнопку сохранения.
- Минимальная интерактивная область — **44 × 44 px**.
- Все основные действия доступны пальцем и, где возможно, одной рукой.
- Текст остаётся читаемым, контраст не строится исключительно на цвете.
- Цвета и стили реализуются через дизайн-токены: визуальная система будет предоставлена отдельно.

## 13. Локаль, даты и деньги

- Только русский язык; переключатель языка отсутствует.
- Валюта — российский рубль (`₽`).
- Копейки не используются.
- Отображение денег: `125 400 ₽` (пробел как разделитель тысяч).
- Локальная дата берётся из часового пояса устройства; пользователь может вручную выбрать нужную дату операции.
- Названия месяцев — на русском.

## 14. Нефункциональные требования

- Данные сохраняются между перезапусками приложения и браузера, пока пользователь не очищает хранилище Safari.
- Интерфейс и расчёты обновляются сразу после любого CRUD-действия, без ручного обновления страницы.
- Приложение не требует подключения к интернету для основной функциональности.
- Ошибка одного некорректного пользовательского ввода не должна приводить к потере уже сохранённых данных.
- Использовать простую, поддерживаемую архитектуру: изолированный доменный слой расчётов и UI-компоненты, не содержащие дублирующих финансовых формул.
- Все вычисления сумм выполнять целыми рублями; не использовать float для денежной арифметики.

## 15. Реализационные заметки для агента

- Создать единый модуль/сервис селекторов расчётов: баланс, свободные деньги, фактический резерв, лимит, остаток лимита, категоризацию расходов. UI должен получать уже вычисленные значения из него.
- Все списки и диаграмма должны фильтроваться по календарному месяцу выбранной даты операции.
- Расходы будущих периодов нельзя создавать как `expense`: направлять пользователя к сущности будущего платежа.
- Операция долга не должна одновременно считаться обычным расходом: она уменьшает баланс и долг, но исключается из суммы, уменьшающей лимит.
- По возможности хранить транзакции как источник истины, а агрегаты долга и резерва вычислять детерминированно. Это упрощает корректный перерасчёт после редактирования истории.
- Логику дат тестировать на границе месяцев, високосного года и при смене часового пояса устройства.
- Не добавлять неутверждённые функции под видом «задела»: MVP сознательно минимален.

## 16. Приёмочные критерии MVP

### Функциональная готовность

- [ ] При первом запуске можно пройти настройку начального остатка, долга, категорий и плана месяца.
- [ ] План месяца автоматически рассчитывает лимит как `планируемый доход − плановый резерв`.
- [ ] Можно добавить, изменить и удалить расход; диаграмма, баланс и лимит пересчитываются сразу.
- [ ] Можно добавить, изменить и удалить доход; общий остаток пересчитывается сразу.
- [ ] Можно добавить, изменить и удалить резерв; свободные деньги и прогресс резерва пересчитываются сразу.
- [ ] Можно создать будущий платёж с суммой, категорией и датой.
- [ ] За день до будущего платежа виден внутренний reminder.
- [ ] Будущий платёж можно отметить как оплаченный, изменить предзаполненную сумму/дату и создать из него фактический расход.
- [ ] Оплаченное напоминание сохраняется в истории со статусом «Оплачено».
- [ ] Можно зафиксировать платёж по долгу; баланс, остаток долга и фактический резерв уменьшаются, а месячный лимит не меняется.
- [ ] Разрешены отрицательные показатели; операции не блокируются из-за недостатка денег или резерва.
- [ ] На Главной крупно отображается «Осталось потратить», а также общий остаток, свободные деньги и кольцевая диаграмма с суммами категорий.
- [ ] История операций сгруппирована по датам и различает все типы операций.
- [ ] Категории и источники доходов можно создавать, редактировать, упорядочивать и архивировать; история при этом не теряется.
- [ ] Операции прошлого месяца можно редактировать, и зависимые показатели пересчитываются.

### Техническая и UX-готовность

- [ ] Приложение работает в Safari на iPhone в вертикальной ориентации.
- [ ] Его можно установить на главный экран как PWA и открыть без адресной строки.
- [ ] После первой загрузки основные сценарии работают без подключения к интернету.
- [ ] После закрытия и повторного открытия приложения локальные данные не теряются.
- [ ] Нет горизонтальной прокрутки; формы полноэкранны и не ломаются при открытой экранной клавиатуре.
- [ ] Все основные интерактивные элементы имеют область нажатия не менее 44 × 44 px.
- [ ] В проекте отсутствуют функции из раздела «Не входит в MVP».

## 17. Возможные следующие итерации
