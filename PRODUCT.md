# Мои финансы — продуктовый контекст

Этот файл — постоянный ориентир для всех последующих итераций. Перед изменением продукта агент должен сверяться с ним. Подробная реализация может меняться, но решения ниже нельзя отменять или размывать без явного согласования с пользователем.

## Зачем существует продукт

«Мои финансы» — личное мобильное приложение для контроля денег в период строгой экономии. Оно помогает пользователю:

- быстро фиксировать фактические доходы и расходы;
- понимать, сколько ещё можно безопасно потратить до конца месяца;
- соблюдать месячный лимит;
- откладывать деньги на обязательную выплату долга;
- видеть, куда уходят деньги по категориям.

Это продукт **для одного человека**, а не универсальная бухгалтерия или банковский агрегатор.

## Главный критерий пользы

Пользователь открывает приложение и примерно за пять секунд понимает:

1. сколько ещё можно потратить в текущем месяце;
2. сколько денег есть фактически и сколько из них свободно;
3. успевает ли она собрать резерв на обязательный платёж.

Успех — пользователь соблюдает лимит и накапливает нужную сумму на долг.

## Неподвижные продуктовые принципы

1. **Простота важнее полноты.** Не добавлять поля, экраны и аналитику без доказанной пользы для ежедневного контроля денег.
2. **План важнее бухгалтерии.** Приложение должно помогать принимать решение «можно ли тратить», а не только строить историю операций.
3. **Минимум ввода.** Обычная расходная операция: сумма, категория, дата. Доход: сумма, источник, дата.
4. **Факт отделён от плана.** Планируемый доход не является деньгами на балансе. Плановый резерв не является фактически отложенным резервом.
5. **Все действия обратимы.** Операции можно исправить или удалить, а все показатели пересчитываются сразу.
6. **Mobile-first.** Основная среда — iPhone и Safari, вертикальная ориентация, PWA.
7. **Офлайн-first с защищённым хранением.** Приложение работает без сети на локальной копии данных. После входа изменения синхронизируются с личным сервером и базой данных; серверная копия защищает историю при смене или потере устройства.

## Финансовая логика, которую нельзя нарушать

### Месячный план

В начале каждого календарного месяца пользователь задаёт:

- планируемый доход;
- плановый резерв на долг.

Месячный лимит рассчитывается так:

`лимит = планируемый доход − плановый резерв на долг`

Обычные расходы уменьшают лимит. Платёж по долгу — нет, потому что резерв уже был учтён в плане.

### Три разных показателя денег

| Показатель | Смысл |
|---|---|
| Общий остаток | Начальный остаток + фактические доходы − обычные расходы − платежи по долгу |
| Свободные деньги | Общий остаток − фактически отложенный резерв |
| Осталось потратить | Месячный лимит − обычные расходы текущего месяца |

### Резерв и долг

- Операция «Резерв» не уменьшает общий остаток, но уменьшает свободные деньги.
- Фактический резерв — накопленные операции резерва за вычетом платежей по долгу.
- Платёж по долгу уменьшает общий остаток, текущий остаток долга и фактический резерв; месячный лимит не уменьшается.
- Отрицательные остатки допустимы: приложение показывает реальную ситуацию и не блокирует сохранение операции.

### Будущие платежи

- Это напоминания, а не фактические расходы.
- До подтверждения они не влияют ни на баланс, ни на лимит.
- За один день до даты внутри приложения показывается напоминание.
- При «Оплачено» пользователь создаёт реальный расход с возможностью поправить сумму и дату.

## Главный экран

Главное число — крупная карточка **«Осталось потратить»**.

На экране без прокрутки также видны:

- общий остаток;
- свободные деньги;
- кольцевая диаграмма расходов за месяц;
- суммы расходов по категориям (без процентов).

Не перегружать Главную лентой операций, расширенной аналитикой, календарями или дополнительными виджетами.

## MVP сейчас

Поддерживаются: доходы, расходы, резерв, будущие платежи, платежи по долгу, месячный план, категории, источники дохода, данные долга и история операций.

Стартовые категории: продукты, транспорт, коммунальные платежи, подписки, связь, долги, непредвиденные расходы, прочее.

Стартовые источники дохода: зарплата, самозанятость, проценты по вкладу, прочее.

## Хранение и синхронизация

- Данные финансового приложения хранятся локально в IndexedDB и на личном сервере пользователя.
- Локальная база остаётся рабочей копией: ввод, просмотр и расчёты доступны офлайн.
- При появлении сети приложение синхронизирует изменения с сервером. Серверная версия используется для восстановления данных на новом устройстве.
- Доступ защищён личной учётной записью с e-mail и паролем. Пароль не хранится в открытом виде.
- Первый вход на существующем устройстве запускает безопасную миграцию: локальные данные отправляются на сервер только после явного подтверждения пользователя.
- Сервер не меняет финансовые формулы и не заменяет локальные данные без подтверждённой синхронизации.

## Сознательные границы MVP

Пока не добавлять: банковские интеграции, импорт, чеки, несколько счетов или валют, семейный бюджет, категории с лимитами, сравнение месяцев, расширенную аналитику, подкатегории, комментарии, накопительные цели, экспорт, push-уведомления и десктопную версию.

Любая функция из этого списка должна обсуждаться как отдельная продуктовая итерация, а не попадать в продукт «по умолчанию».

## Как работать с этим файлом в следующих итерациях

Перед реализацией новой идеи агент должен ответить:

1. Помогает ли она контролировать лимит или резерв на долг?
2. Не усложняет ли она ежедневный ввод?
3. Не смешивает ли она плановые и фактические деньги?
4. Не противоречит ли она формулам и границам выше?

Если ответ на любой вопрос неоднозначен, агент должен сначала запросить решение пользователя.
